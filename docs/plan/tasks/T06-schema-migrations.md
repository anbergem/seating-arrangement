# T06 — Schema, migrations, local migration runner, readiness route

Goal: the app-owned schema as Wrangler migrations, the same SQL applied to the local SQLite file,
a generated migrations manifest, reset script, and the `/api/ready` route.

Depends on: T03, T05. Read: F8, F10, F13 (`db-tool-scoping`); B10, B15, B19 (ready route);
D05, D06, D07.

## Steps

1. `migrations/0001_init.sql` with the B10 SQL verbatim (statement order as shown). Remove
   `migrations/.gitkeep`.
2. `server/db/schema.ts`: define `customers`, `jobs`, `operations`, `idempotencyKeys` with the
   framework helpers from `@agent-native/core/db/schema` mirroring every column (text/integer);
   this file is a typed mirror only. `server/db/index.ts`: `export const getDb = createGetDb(schema)`.
3. `scripts/migrate-local.mjs` (ESM): reads `DATABASE_URL` (default `file:./data/app.db`; refuse
   anything not starting with `file:`), creates the directory, opens it with `@libsql/client`
   (`createClient({ url })`), ensures table
   `d1_migrations (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE, applied_at TEXT NOT NULL)`,
   lists `migrations/*.sql` sorted, applies each not yet recorded inside one transaction per
   file (split statements on `;` followed by a newline; ignore empty and comment-only
   statements; `PRAGMA foreign_keys = ON` first), records the file name, prints
   `applied <name>` or `up to date`.
4. `scripts/gen-migrations-manifest.mjs`: writes `src/infrastructure/migrations-manifest.ts`
   containing `export const MIGRATION_FILES = [ ...sorted names ] as const;` with a header
   comment `// generated by scripts/gen-migrations-manifest.mjs — do not edit`. Commit the
   generated file. Hook it into `scripts/build-worker.mjs` (T02 left the call site) and into
   `db:migrate` (`node scripts/gen-migrations-manifest.mjs && node scripts/migrate-local.mjs`).
5. `scripts/reset-local.mjs`: deletes `data/app.db`, `data/app.db-shm`, `data/app.db-wal`, and
   `.wrangler/state`; then runs `db:migrate` and `db:migrate:worker` (the latter needs `dist/`;
   if `dist/` is absent print a notice and skip the Worker part).
6. `package.json` scripts: `db:migrate`, `db:reset`, `db:migrate:staging`,
   `db:migrate:production` per B15.
7. `server/routes/api/ready.get.ts`: uses `getDbExec()` to `SELECT name FROM d1_migrations`
   (wrap in try/catch: missing table → applied 0); compares the set with `MIGRATION_FILES`
   (D1's migrations table stores the file name in `name`; verify with
   `wrangler d1 migrations apply example-jobs-local --local` followed by
   `wrangler d1 execute example-jobs-local --local --command "select * from d1_migrations"` and
   adapt the comparison to the stored form); responds `{ ready: boolean, migrations: { applied, expected, missing: string[] } }`
   with status 200 when ready, 503 otherwise. Register the route as public in
   `createAuthPlugin({ publicPaths: ["/api/ready"] })` in `server/plugins/auth.ts`.
8. `tests/unit/infrastructure/migrations-manifest.test.ts`: the manifest equals the sorted
   directory listing of `migrations/*.sql`.
9. Verify: `pnpm db:reset` creates `data/app.db` with the four tables; `pnpm build:worker &&
   pnpm db:migrate:worker` applies `0001_init.sql` to local D1; with `pnpm dev:worker:serve`
   running, `curl -s -w '%{http_code}' http://127.0.0.1:8787/api/ready` returns 200 and
   `applied === expected === 1`.

## Deliverables

`migrations/0001_init.sql`, `server/db/{schema,index}.ts`, `scripts/{migrate-local,gen-migrations-manifest,reset-local}.mjs`,
`src/infrastructure/migrations-manifest.ts`, `server/routes/api/ready.get.ts`,
`server/plugins/auth.ts`, `package.json`, `tests/unit/infrastructure/migrations-manifest.test.ts`.

## Acceptance

```bash
pnpm check
pnpm db:reset
node -e "const {createClient}=require('@libsql/client');createClient({url:'file:./data/app.db'}).execute(\"select name from sqlite_master where type='table' and name in ('customers','jobs','operations','idempotency_keys')\").then(r=>{if(r.rows.length!==4)process.exit(1)})"
pnpm build:worker && pnpm db:migrate:worker
```
plus the step 9 `/api/ready` transcript.
