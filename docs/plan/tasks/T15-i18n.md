# T15 — Internationalization

Goal: complete `en-US` and `nb-NO` app catalogs, language settings, the catalog guard, and the
self-invalidating wiring for Norwegian.

Depends on: T14. Read: F14; D19.

## Steps

1. `app/i18n/en-US.ts`: every key used by `useT()` in `app/` (run the guard to find missing
   ones), grouped `nav`, `jobs`, `customers`, `activity`, `status`, `errors` (one key per
   `AppErrorCode` — all eight including `EXTERNAL` — plus the `UNKNOWN` fallback for a failure
   that carries no code), `common`. Placeholders are `{{name}}`: the framework substitutes no
   other form (F14), so a single-brace `{name}` reaches the screen verbatim.
2. `app/i18n/nb-NO.ts`: a complete Norwegian Bokmål translation with identical keys and
   placeholders. Translation quality needs human review: add a `// REVIEW: translated by <who>,
   needs native review` header line; the maintainer removes it after review.
3. Delete the scaffold's other app locale files (`zh-CN.ts`, ... ) and set
   `createAgentNativeI18nCatalog({ messages: enUS, localeLoaders: { /* see below */ }, supportedLocales: ["en-US"] })`.
   Wire Norwegian as:
   ```ts
   localeLoaders: {
     // Norwegian is not in the framework's locale list yet (BuilderIO/agent-native#3985).
     // @ts-expect-error — remove this line and add "nb-NO" to supportedLocales when the framework accepts it
     "nb-NO": () => import("./nb-NO"),
   },
   ```
   If TypeScript does not error on the key (the type is looser than expected), remove the
   `@ts-expect-error` line, keep the loader, and record a discrepancy with the observed type.
4. `agent-native.config.ts` `translations.locales` stays `["en-US"]` until upstream adds
   Norwegian.
5. Settings page: ensure `LanguagePicker` renders (framework settings route) and that
   `set-localization-preference` persists a supported locale (verify `de-DE` switches the
   framework UI language, app strings fall back to English by design; then switch back).
6. Guard: add script `guard:i18n` running the framework's catalog guard for `app/i18n` (find
   the exact command in `docs/content/internationalization.mdx`; if the guard is only available
   inside the framework monorepo, write `scripts/check-i18n-catalogs.mjs` that checks key parity
   and placeholder parity between `en-US.ts` and `nb-NO.ts`, rejects a placeholder form the
   framework never substitutes, and checks that every `t("...")` key in `app/` exists in
   `en-US.ts`; record a discrepancy either way). Add it to `pnpm check` with regression
   fixtures in `tests/guards/i18n-catalogs.test.mjs` (D27).
7. Dates and numbers: confirm every date in the UI goes through `useFormatters()`; no
   `toLocaleDateString` in `app/`.

## Deliverables

`app/i18n/{index,en-US,nb-NO}.ts`, deleted scaffold locales, `scripts/check-i18n-catalogs.mjs`
(if needed), `package.json`, `agent-native.config.ts`.

## Acceptance

```bash
pnpm check
pnpm guard:i18n
grep -rn "toLocaleDateString\|toLocaleString" app/ ; test $? -eq 1
```
